Mecanismo de Detección del Árbol de Decisión (Notebook 03 · Sección 3)

Análisis formal de las reglas de partición aprendidas por el clasificador CART con profundidad máxima 4 y pesos balanceados.

CART (Gini Impurity)
1. División Primaria 49.60% Imp.

Tot size ≤ 67.0 bytes

El discriminador más potente del dataset es la longitud de la trama. Las herramientas automatizadas de DDoS generan tramas sintéticas mínimas fijas:

  • • DDoS SYN: 54B exactos (14 Eth + 20 IP + 20 TCP).
  • • DDoS UDP: 50B exactos (14 Eth + 20 IP + 8 UDP + 8 pad).
  • • Benigno IoMT: 80.8B a 1500B (payload médico).
→ Si Tot size > 67B, el flujo se clasifica como Benigno de inmediato (99.97% recall).
2. Clasificación de Variante 48.96% Imp.

syn_flag_number > 0.5

Entre los paquetes que cumplen la condición de trama corta (≤67B), el árbol examina el flag TCP SYN:

  • • syn_flag == 1: Inundación SYN flood. Se clasifica como DDoS SYN.
  • • syn_flag == 0: El paquete no solicita conexión TCP SYN; pasa a la rama UDP.
→ La presencia del flag SYN discrimina el 99.68% de las conexiones maliciosas SYN.
3. Saturación UDP 1.44% Imp.

Protocol == 17 ó Rate > 10k

Las divisiones restantes corroboran el tipo de protocolo (UDP = 17) y la frecuencia masiva de ráfaga:

  • • Rate > 20.000 pkts/s: Saturación extrema de búfer.
  • • Variance == 0: Ausencia total de fluctuación humana.
→ Se etiqueta como DDoS UDP con 99.94% de precisión en la prueba oficial.

Lección de Ciencia de Datos: El árbol depende en un 98.56% de solo 2 variables (Tot size y syn_flag_number). Esto genera una solución ultra-rápida y precisa dentro del dominio, pero también explica el sesgo de variantes del escenario V1: si una variante como UDP no tiene el flag SYN y nunca fue vista, el árbol toma el atajo erróneo y la cataloga como benigna. Por ello, en el Notebook 04 los ensambles de boosting (LightGBM/XGBoost) distribuyen la importancia hacia Variance y Rate.
